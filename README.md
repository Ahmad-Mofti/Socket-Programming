## فاز چهارم — (GUI + Features)


# 1. ماژول سرور (server.py) و توابع آن

در این ماژول، سرور نقش هسته مرکزی سیستم پیام‌رسان را دارد و تمام ارتباطات بین کاربران را مدیریت می‌کند.

---

## 1.1 تابع `handle_client(client_socket, address)`

### کارکرد:
این تابع مسئول مدیریت کامل یک کلاینت از لحظه اتصال تا قطع ارتباط است.

### ورودی‌ها:
- `client_socket`: سوکت کلاینت متصل شده
- `address`: آدرس IP و پورت کلاینت

### وظایف:
- دریافت نام کاربری اولیه (username)
- ثبت کلاینت در ساختار `clients`
- مدیریت پیام‌های دریافتی از کلاینت
- تشخیص نوع پیام (عادی، خصوصی، دستور)
- مدیریت قطع اتصال کاربر

### جریان داده:
Client → Socket → handle_client → Process → broadcast / routing → Other clients


---

## 1.2 تابع `broadcast(message, sender_socket)`

### کارکرد:
ارسال یک پیام به تمام کلاینت‌های متصل به جز فرستنده.

### ورودی‌ها:
- `message`: پیام به صورت bytes
- `sender_socket`: کلاینت ارسال‌کننده پیام

### وظایف:
- پیمایش لیست کلاینت‌ها
- ارسال پیام به همه کلاینت‌ها
- حذف کلاینت‌های غیرقابل دسترس

---

## 1.3 تابع `remove_client(client_socket)`

### کارکرد:
حذف ایمن یک کلاینت از سیستم.

### وظایف:
- حذف کلاینت از دیکشنری `clients`
- بستن socket مربوطه
- آزادسازی منابع سیستم

---

# 2. ماژول کلاینت (client.py)

این ماژول رابط کاربری گرافیکی و ارتباط کاربر با سرور را مدیریت می‌کند.

---

## 2.1 تابع `send_message()`

### کارکرد:
پردازش پیام کاربر و ارسال آن به سرور.

### انواع پیام:

#### 1. پیام عادی:
- ارسال پیام به صورت broadcast

#### 2. پیام خصوصی:
- پیام‌هایی با فرمت `@username`
- ارسال فقط به کاربر مشخص

#### 3. دستورات:
- `/users` → دریافت لیست کاربران آنلاین
- `/exit` → خروج از چت

### جریان داده:
GUI → send_message → Socket → Server


---

## 2.2 تابع `receive_messages()`

### کارکرد:
دریافت پیام‌های سرور به صورت real-time.

### ویژگی‌ها:
- اجرا در یک Thread جداگانه
- جلوگیری از قفل شدن GUI
- نمایش پیام‌ها در رابط کاربری

### جریان داده:
Server → Socket → Thread → GUI


---

## 2.3 تابع `add_message(msg)`

### کارکرد:
نمایش پیام‌ها در محیط گرافیکی.

### وظایف:
- اضافه کردن پیام به chat box
- اسکرول خودکار به آخر پیام‌ها

---

# 3. جریان کلی داده (System Data Flow)

## 3.1 پیام عمومی (Broadcast)
1. کاربر پیام را در GUI وارد می‌کند  
2. تابع `send_message()` پیام را ارسال می‌کند  
3. سرور در `handle_client()` پیام را دریافت می‌کند  
4. پیام به `broadcast()` ارسال می‌شود  
5. همه کلاینت‌ها پیام را دریافت و نمایش می‌دهند  

---

## 3.2 پیام خصوصی (Private Message)
1. پیام با `@username` ارسال می‌شود  
2. سرور پیام را در `handle_client()` پردازش می‌کند  
3. پیام فقط برای کاربر هدف ارسال می‌شود  
4. فرستنده نسخه مخصوص PM را مشاهده می‌کند  

---

## 3.3 دستورات سیستم
- `/users` → نمایش کاربران آنلاین  
- `/exit` → خروج از سیستم و حذف کلاینت  

---

## 3.4 مدیریت قطع اتصال
1. اتصال کلاینت قطع می‌شود  
2. `remove_client()` اجرا می‌شود  
3. کلاینت از سیستم حذف می‌شود  
4. سایر کاربران بدون اختلال به کار ادامه می‌دهند  

---

# 4. ویژگی‌های نهایی سیستم

- Multi-user chat system
- Real-time messaging
- Private messaging (@username)
- User list command (/users)
- GUI based client (Tkinter)
- Thread-based concurrency
- Timestamp support
- Graceful disconnect handling
